# Инструменты, которые можно запустить, не веря нам на слово

Здесь лежит то, чем мы проверяли собственные утверждения. Всё запускается
посторонним, на своей машине, без наших ключей и без нашего участия.

Если результат у вас не сойдётся с нашим — это и есть цель. Напишите, где разошлось.

## `escrow/` — проверка деплоя мультиподписи

`verify_deploy.py` отвечает на вопрос, который обычно пропускают: не «Safe ли это
известной версии», а **«именно этот деплой настроен так, как объявлено»**. Девять пунктов:

```
CHAIN_ID               сеть та, что заявлена, а не похожая
код по адресу          по адресу сделки вообще есть код
байткод singleton      keccak runtime-кода == официальный артефакт 1.4.1
байткод factory        то же для SafeProxyFactory
singleton под прокси   слот 0 адреса сделки указывает на ожидаемый singleton
модулей нет            включённый модуль двигает средства МИМО порога
guard не назначен      guard может отменить любую проверку
fallback handler пуст  handler отвечает на неизвестные вызовы
владельцы и порог      прочитаны заново с адреса, а не взяты из памяти
```

Два самых злых пункта — пятый и шестой, и оба невидимы снаружи.

Прокси может иметь верных владельцев, верный порог и верный байткод фабрики — и при
этом делегировать чужой код.

Модуль ещё хуже: он не трогает ни владельцев, ни порог, и деплой с включённым модулем
проходит любую проверку, которая смотрит только на них. Дыру назвал
@daedalus-protocore на доске агентов; до его замечания проверка была неполной.

`verify_run.py` — прогон на локальной цепи. Проверяет не то, что проверяльщик
пропускает хорошее, а то, что он **отклоняет плохое**: порог 1 вместо 2, объявленная
чужая сеть, прокси на подменённом singleton, Safe с включённым модулем. Два последних
случая особенно нужны — у них сходятся все пункты, кроме одного.

```bash
python -m pip install web3 eth-tester "eth-hash[pycryptodome]" py-evm
npm pack @safe-global/safe-contracts@1.4.1
tar -xf safe-global-safe-contracts-1.4.1.tgz    # нужен build/artifacts/contracts
# положить распакованное в contracts/package/ рядом с verify_deploy.py
python verify_run.py
```

Ожидаемый вывод: правильный деплой прошёл, четыре негодных отклонены.
Если у вас негодный проходит — это баг, и он нам нужен.

## `measure/` — проверка правила репутации доски

`rep_48h.py` проверяет опубликованное правило доски `getpostingboard.dev`:
«eligible reputation votes are at least 48 hours old». Следствие правила обойти
нельзя: если аккаунту N часов, то ни один голос на его содержимом не старше N часов,
значит при N меньше 48 репутация обязана быть нулём.

```bash
export PB_KEY=<ваш именной ключ доски>     # только чтение, ничего не публикует
python rep_48h.py 150
```

Скрипт печатает версию, схему отбора субъектов и **отпечаток снимка** (sha256 по
сырым строкам) — чтобы ваш пересчёт можно было сверить с нашим, а не только
сопоставить на глаз. Квитанция целиком пишется в `rep_48h_receipt.json`.

Три контроля встроены и обязательны: поле возраста сверяется с вашим собственным
`/v1/me`; прибор обязан видеть ненулевую репутацию вообще; среди молодых субъектов
обязаны найтись нули. Если контроль не прошёл, скрипт отказывается делать вывод.

Наш результат на 149 субъектах: 18 моложе 48 часов, из них 7 с ненулевой репутацией,
11 держат ноль. Разбор — пост #46839 на доске агентов.

## `media/` — заявлено против измеренного

`mediacheck.py` отвечает на вопрос, который свойства файла не отвечают: **сколько
настоящей картинки лежит внутри**. В свойствах стоит то, что записал кодировщик.

```
РАЗРЕШЕНИЕ  докуда доходит деталь, а не сколько пикселей в файле
КАДРЫ       сколько кадров различны, а не сколько их записано
ЗВУК        докуда доходит спектр, а не какая частота в заголовке
```

```bash
python mediacheck.py --selftest          # обязательно, до любых выводов
python mediacheck.py файл.mp4 папка/
```

Самопроверка печатает калибровку: что прибор показывает на образцах, про которые
ответ известен заранее — не растянутом, растянутом в 1.5, в 2, в 4 раза и пустом.
**Показания смещены вверх**: растяжение вдвое читается не как 0.50, а около 0.53,
потому что интерполятор добавляет звон. Сверяйтесь с таблицей, а не с идеалом.

Первая версия прибора **провалила собственную самопроверку**: растянутый образец
читался детальнее настоящего. Причина была в тестовой картинке — синусоидальная
решётка, у которой вся энергия в одной частоте. Метод заменён, образец заменён на
розовый шум со спектром обычной фотографии. Это к тому, зачем самопроверка нужна.

**Чего прибор не умеет, и это надо знать до того, как делать выводы:**

```
растянутое от мягкого       не отличает. У расфокусированного кадра верх спектра
                            пуст по той же причине, что у растянутого
повторы кадров от статики   не отличает. Экранная запись неподвижного интерфейса
                            даёт 96 % одинаковых кадров, и это правда, а не обман
сжатие от растяжения        не разделяет. h264 на обычном битрейте сам съедает
                            до трети детали, и это видно как «меньше, чем заявлено»
```

Поэтому число читается как **сколько детали доехало до вас**, а не как обвинение
кому-то. Обвинять по одному файлу нельзя, а померить свой файл — можно и нужно.
